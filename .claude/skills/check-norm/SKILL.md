# Проверка нормы по приказу

Цель: каждое правило в `data/rules.json` совпадает с действующим текстом приказа (404н — обследования, 1122н — прививки), а в Wiki стоит честная дата проверки.

## Шаги

1. **Что проверяем.** Если пользователь назвал обследование или прививку, найди правило по `test` или `title` в `rules` или `vaccines`. Если не назвал, проверь все правила по очереди.
2. **Откуда берём текст.** Открой `url` источника из `sources` (обычно base.garant.ru). consultant.ru из облака не открывается, используй Garant или Firecrawl. Сайты-пересказы не являются источником.
3. **Сверка по пункту `clause`.** Для каждого правила сравни с текстом:
   - пол (`sex`);
   - возраст (`age_min`, `age_max`; возраст считается по календарному году);
   - периодичность (`interval_months`, `once`);
   - для прививок — условия (`only_if`, `condition`, `who`);
   - редакция: не изменён ли пункт новым приказом (смотри «с изменениями» и дату редакции).
4. **Итог.** Покажи таблицу «правило → что в приказе → совпадает / расходится» с цитатой и ссылкой. Ничего не правь молча.
5. **Если расходится.** Поправь `data/rules.json`, а затем добавь или обнови тест в `tests/test_engine.py`. Тесты запустятся сами после правки. Если правило меняет план демо-пациентов, проверь `tests/test_app.py`.
6. **Дата проверки.** В статьях `data/wiki/*.md`, где в `sources` указан проверенный источник, обнови `checked:` на сегодняшнюю дату. Если статьи с таким источником нет, ничего не делай.
7. Работа идёт через ветку `claude/*` и запрос на слияние. Пользователю объясняй результат простыми словами, без программистских терминов.

## Нельзя

- Менять норму без цитаты из официального текста.
- Ставить дату проверки, если источник не открылся. В этом случае так и скажи.
